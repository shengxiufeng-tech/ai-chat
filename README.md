# 💬 AI 对话室

让多个 AI 角色互相对话的本地 Web 应用。你可以当主持人开场、随时插话、点名谁来回答，也可以只旁观。
后续会加入 **COC 7 版跑团模式**：AI 当守秘人（KP），带你入门跑团。

模型通过 [Magpie](https://github.com/yetone/magpie) 的本地网关接入（也支持任何 OpenAI 兼容接口），每个 AI 角色可以用不同的模型。

## 快速开始

需要 Node.js 22.12 或更高版本（推荐安装 Node.js 22 LTS 或更新的 LTS 版本）。

```bash
npm install
npm run dev
```

然后打开 <http://localhost:5173>。

- 先打开 Magpie，保持它运行。应用默认连接 Magpie 网关 `http://127.0.0.1:3425/v1`，并读取你在 Magpie 里启用的全部模型。
- 没开 Magpie 也能先体验：在左下角「⚙ 设置」里把地址改成 `mock`，就会用模拟回复。

想长期使用的话，也可以打包后只跑一个服务：

```bash
npm run build
npm start          # 打开 http://localhost:8787
```

## 怎么用

1. **新建房间**：选一个预设（圆桌闲聊 / 辩论赛 / 头脑风暴 / 空白房间），选好角色默认使用的模型。
2. **开场**：你默认是主持人，在输入框里说一句开场白或抛出话题，AI 就会接话。
3. **让 AI 们自己聊**：点「▶ 开始自动对话」。AI 连续发言达到设定次数后会自动暂停，避免 token 用量失控。
4. **随时插话**：
   - 直接发送：等正在发言的 AI 说完，下一位会看到你的话。
   - 「打断并发送」：立刻打断正在说话的 AI。
   - 在消息里写 `@名字`（或点输入框上方的名字）：让那位角色优先接话。
5. **控制节奏**：
   - 「⏭ 下一位」：只让一位 AI 说一句。
   - 角色旁边的「发言」：点名让 TA 说。
   - 「⏹ 停止」：立刻打断并暂停。
6. **调整角色**：在右侧「角色」里可以改名字、头像、人设、模型和温度，开关控制是否参与自动轮换，▲▼ 调整发言顺序。满意的角色可以「存为模板」，在其他房间复用。
7. **房间设置**：场景/话题、你的名字和身份（主持人 / 参与者 / 旁观者）、发言顺序、自动暂停、回复篇幅等。
8. 消息可以编辑、删除；最后一条 AI 消息可以重新生成；整场对话可以导出为 Markdown。

### 谁来说下一句？

| 模式 | 说明 |
| --- | --- |
| 轮流发言 | 按右侧角色列表的顺序依次发言 |
| AI 主持人决定 | 每轮多调用一次模型，根据上下文挑出最该接话的人（谁被提问、被反驳就让谁回应），对话更自然。建议在房间设置里给它配一个便宜快速的模型 |
| 手动点名 | 只有你点「发言」或 `@名字` 时 AI 才说话 |

## 关于 Magpie

Magpie 在本机 `127.0.0.1:3425` 提供 OpenAI 兼容的 `/v1/chat/completions` 和 `/v1/models` 接口，本应用的后端直接调用它：

- 模型列表从 Magpie 动态读取。你在 Magpie 里新接的模型（开源模型、GPT、Gemini、Grok……）会直接出现在角色的模型下拉框里，不用改代码。
- 本机调用不需要真实的 key。默认发送 `magpie-ai-chat`，这样 Magpie 的用量统计里会把这些调用单独记为 ai-chat。
- 调用发生在后端，而不是浏览器里，因为 Magpie 会拒绝来自网页的直接请求。所以本应用需要和 Magpie 运行在同一台电脑上。
- 推理模型的思考过程（`reasoning_content` 字段，或正文里的 `<think>` 标签）会单独折叠显示，不计入对话内容。

也可以不用 Magpie，在「设置」里填任何 OpenAI 兼容地址和 key（例如各家官方 API、Ollama 的 `http://127.0.0.1:11434/v1`）。

## 配置

网页里的「设置」保存在 `data/settings.json`，优先级最高。也可以用环境变量提供默认值（见 `.env.example`）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_BASE_URL` | `http://127.0.0.1:3425/v1` | 模型服务地址，填 `mock` 使用模拟回复 |
| `LLM_API_KEY` | `magpie-ai-chat` | API Key |
| `LLM_DEFAULT_MODEL` | 空 | 新角色的默认模型 |
| `PORT` | `8787` | 后端端口 |
| `DATA_DIR` | `./data` | 数据目录（房间、模板、设置都是 JSON 文件） |

## 项目结构

```
shared/types.ts        前后端共用的数据类型
server/
  index.ts             Express 接口 + SSE 实时推送 + 托管前端
  runner.ts            对话调度：选下一位发言者、流式生成、插话 / 暂停 / 打断
  prompt.ts            提示词：每个 AI 从自己的视角看对话历史
  llm.ts               OpenAI 兼容接口的流式调用（含模拟模式）
  store.ts             JSON 文件存储
  presets.ts           内置角色模板和房间预设
web/src/               React 前端
```

几个关键设计：

- **每个 AI 的视角**：调用模型时，这个 AI 自己说过的话作为 `assistant` 消息，其他人（包括你）的话以「【名字】：内容」的形式作为 `user` 消息，同一方连续的消息会合并。系统提示里写明它是谁、其他人是谁，并要求它只代表自己发言。
- **对话循环在后端跑**：关掉网页对话也不会乱掉，重新打开就能看到最新状态。前端通过 SSE 实时接收逐字输出。

开发命令：

```bash
npm run typecheck   # 类型检查
npm test            # 后端单元测试
```
