# 💬 AI 对话室

一个本地运行的 Web 应用，有两种玩法：

- **多人对话**：让多个 AI 角色互相对话。你可以当主持人开场、随时插话、点名谁来回答，也可以只旁观。
- **跑团（COC 7）**：AI 当守秘人（KP），程序负责掷骰子，你扮演调查员。带角色卡、车卡向导和规则助手，适合完全没玩过跑团的新手。

模型通过 [Magpie](https://github.com/yetone/magpie) 的本地网关接入，也支持任何 OpenAI 兼容接口。每个 AI 角色可以用不同的模型和思考强度。

## 快速开始

需要 Node.js 22.12 或更高版本（推荐安装 Node.js 22 LTS 或更新的 LTS 版本）。

```bash
npm install
npm run dev
```

然后打开 <http://localhost:5173>。

- 先打开 Magpie，并保持它运行。应用默认连接 Magpie 网关 `http://127.0.0.1:3425/v1`，读取你在 Magpie 里启用的全部模型和它们支持的思考强度。
- 没开 Magpie 也能先体验：在左下角「设置」里把地址改成 `mock`，就会用模拟回复。

想长期使用的话，可以打包后只跑一个服务：

```bash
npm run build
npm start          # 打开 http://localhost:8787
```

## 管理房间

左侧栏的房间列表：

- **搜索**：顶部的搜索框（快捷键 Ctrl / ⌘ + K）会同时搜索房间名、AI 名字、场景和所有消息内容，命中的那句话会显示在房间名下面，关键词高亮。按 Esc 清空。
- **重命名**：鼠标移到房间上点「⋯ → 重命名」，或者直接双击房间名。也可以双击房间顶部的标题来改。
- **删除**：「⋯ → 删除房间」，或者房间右上角的「⋯」菜单。删除前会确认，建议先用「导出与分享」备份成 JSON。

## 多人对话

1. **新建房间**：选一个预设，然后选好角色默认使用的模型。预设有：
   - 圆桌闲聊
   - 辩论赛
   - 头脑风暴
   - 拟人对话
   - 空白房间
2. **开场**：你默认是主持人，在输入框里说一句开场白或抛出话题，AI 就会接话。
3. **让 AI 们自己聊**：点「开始自动对话」。AI 连续发言达到设定次数后会自动暂停，避免 token 用量失控。
4. **随时插话**：
   - 直接发送：等正在发言的 AI 说完，下一位会看到你的话。
   - 「打断并发送」：立刻打断正在说话的 AI。
   - 在消息里写 `@名字`，或点输入框里的名字：让那位角色优先接话。
5. **控制节奏**：
   - 「下一位」：只让一位 AI 说一句。
   - 角色旁边的喇叭按钮：点名让 TA 说。
   - 「停止」：立刻打断并暂停。
6. **调整角色**：在右侧「角色」里可以修改每个角色的设定，满意的角色可以「存为模板」，在其他房间复用。
   - 可改：名字、头像、人设、模型、思考强度、温度。
   - 开关：是否参与自动轮换。
   - 箭头：调整发言顺序。
7. **房间设置**：
   - 提示词风格
   - 场景 / 话题
   - 你的名字和身份（主持人 / 参与者 / 旁观者）
   - 发言顺序、自动暂停、回复篇幅

### 谁来说下一句？

| 模式 | 说明 |
| --- | --- |
| 轮流发言 | 按右侧角色列表的顺序依次发言 |
| AI 主持人决定 | 每轮多调用一次模型，根据上下文挑出最该接话的人（谁被提问、被反驳就让谁回应），对话更自然。建议给它配一个便宜快速的模型 |
| 手动点名 | 只有你点「发言」或 `@名字` 时 AI 才说话 |

### 拟人对话

拟人预设只会告诉每个 AI 一句话：

> 你是一个真实的人，正在和另一个真实的人聊天。请像真人一样和对方自然地对话。

除此之外什么都不加：没有名字、人设、场景、多人对话规则，也没有发言提醒。对话记录里，对方的话就是普通的消息，只有当对方不止一个人时才会在前面加上说话人的名字。

你也可以在任何房间的「房间设置 → 提示词风格」里切换到「拟人」。

## 思考强度

每个 AI 都可以单独设置思考强度，选择器只列出当前模型支持的档位：

- 档位来自 Magpie `/v1/models` 返回的 `supported_reasoning_levels` / `reasoning_levels`。
- 选了档位后，请求里会带上 `reasoning_effort`；选「默认」则不发送，由模型或 Magpie 自己决定。
- 不支持思考强度的模型会提示"不支持调节"。如果模型不在列表里（手动输入的 id），会给出常见档位。

模型和思考强度会显示在三个地方：

- 对话主界面顶部的演员栏：每个 AI 一个标签，点击就能快速切换模型和思考强度。
- 每条消息的名字旁边：显示这句话是用哪个模型、哪个思考强度说的。
- 导出的图片和文件里。

## 跑团（COC 7）

新建房间时选「跑团（COC 7）」：

1. **选剧本**：
   - **雾锁白水镇**：为本应用原创的新手短篇。1927 年江南水乡，失踪的老友和一口会唱歌的井，约 1~2 小时。
   - **AI 即兴剧本**：给一个主题和时代背景，守秘人现场编一个短篇调查故事。
   - **我自己的剧本**：导入剧本文件（txt / md / doc / docx），或者直接粘贴文字。详见下面的「导入剧本（防剧透）」。
2. **配置 AI**：
   - 守秘人的模型和思考强度，建议用你最强的模型。
   - 0~2 位 AI 队友：陪你一起调查，避免一个人冷场。
3. **创建调查员**：车卡向导会一步步带你走完：
   1. 选职业
   2. 掷属性（可以随便重骰）
   3. 分配技能点（有「自动分配」）
   4. 写背景

   不想研究规则的话，直接点「快速生成」。
4. **开始游戏**：守秘人开场，之后由你描述调查员要做什么。

### 导入剧本（防剧透）

网上找到的剧本文件里，往往同时有给玩家的介绍、给守秘人的真相和流程，还有作者信息、更新说明、攻略之类的内容。直接读一遍就被剧透了，所以导入时由 AI 先帮你整理：

1. 选「我自己的剧本」，上传文件（txt / md / doc / docx）或粘贴文字。PDF 请先另存为 docx 或 txt。
2. 守秘人的模型读一遍全文，分出两类内容：
   - **你能看的**：标题、时代背景、一段不剧透的开场介绍、开团须知（推荐人数、时长、适合的职业等）。
   - **只有守秘人能看的**：真相、场景流程、NPC 秘密、结局。默认隐藏，界面上只显示「查看守秘人资料（剧透）」。
3. 标题、时代背景和介绍可以改，确认后创建房间。
4. 游戏时守秘人同时拿到整理好的速览和剧本原文（最多约 12 万字，超出的部分会截断并提示）。文件里的图片不会导入。

整理失败（比如模型没连上、回复格式不对）也不会剧透：界面只提示「已直接使用原文」，原文照样只给守秘人。想重新整理的话，换个模型再选一次文件即可。

### 时代背景

时代背景是一段自由填写的文字，比如「1920 年代，美国新英格兰」「民国时期的中国」「维多利亚时代的英国」「现代」，也可以写得更具体。它有两个作用：

- **守秘人按这个背景讲故事**：交通、通讯、科技、物价、社会风气和人物的说话方式都会贴合这个年代。AI 队友和规则助手也知道这个背景。
- **决定技能列表**：COC 7 的规则书只给了两套标准技能表：1920 年代和现代（多了「计算机使用」「电子学」等）。程序会根据你写的时代自动选：1960 年代以后、写了「现代」「当代」「互联网」之类的用现代技能表，其他都用 1920 年代技能表。

导入剧本时，时代背景由 AI 从剧本里读出来，你也可以改。

游戏中：

- **骰子由程序掷，AI 不能编造结果**：
  - 守秘人需要检定时，会在消息里写一个指令，例如 `[检定:侦查:困难]`、`[理智:1/1d6]`、`[HP:-1d3]`、`[物品:+旧钥匙]`。
  - 程序把指令变成骰子卡片。
  - 你点「掷骰」后，卡片显示掷出的点数、成功等级（大成功 / 极难 / 困难 / 成功 / 失败 / 大失败）和判定说明。
  - 普通技能检定失败后，守秘人会先等你决定：「接受失败」，或者「孤注一掷」再骰一次（可以先写下你打算怎么更努力，这段话会发给守秘人）。直接输入新的行动也算接受失败。理智、幸运、心理学和战斗相关的检定不能孤注一掷。
  - 守秘人要求你掷骰时，AI 队友会等守秘人描述完结果再行动。
  - 结局奖励理智用 `[SAN:+1d6]`，不会被误当成理智检定。
- **技能成长**：模组结束时守秘人会用 `[成长]` 发起技能成长检定，也可以在「调查员」页底部手动发起。程序会列出这次成功使用过的技能（信用评级、克苏鲁神话和属性检定除外），每项掷 1d100，大于当前技能值（或 96 以上）就成长 1d10 点，并自动更新角色卡。
- **角色卡**：
  - 右侧「调查员」页实时显示生命、理智、魔法、幸运、属性、技能和物品。
  - 守秘人造成的伤害、理智损失、获得的物品会自动更新到卡上，你也可以手动调整。
- **角色行动 / 场外**：
  - 输入框可以切换成「场外」：这是你本人在提问（比如问规则），不会推进剧情。
  - AI 队友看不到场外发言。
- **我该做什么？**：卡住时点它，规则助手会给出 3 个可以尝试的行动，点一下就能填进输入框。
- **规则助手**：
  - 右侧「规则助手」页可以随时问规则或"现在发生了什么"。
  - 它能看到游戏记录和你的角色卡，但看不到剧本秘密，也不会剧透。
- **守秘人笔记**：守秘人会用 `[NPC:名字:描述]`、`[线索:标题:内容]` 把重要的 NPC 和你发现的线索记下来。
  - 每记一条，主对话里会出现提示，点「查看笔记」就能打开右侧的「笔记」页。笔记可以修改或删除。
  - 守秘人知道笔记对你可见，所以只记你已经知道的事，不会把剧本真相写进去。
  - 笔记每轮都会发给守秘人，AI 队友和规则助手也能看到，长时间游戏不容易前后矛盾。
  - 新建房间时或在「设置」里可以关闭。
- **秘密备忘**：
  - 守秘人可以用 `[备忘:主题:内容]` 记下自己临时定下、剧本里没写的秘密设定，比如即兴编的真相、NPC 的真实身份、伏笔。同一主题会覆盖更新。
  - 只有守秘人能看到：不会出现在对话、笔记页、搜索和导出里，AI 队友和规则助手也看不到。
  - 用「AI 即兴剧本」时，守秘人会在第一次回复时就把真相和结局条件记进备忘，不会因为它的构思没有保存下来而前后矛盾。
  - 想偷看或删掉，可以在「设置 → 剧透区」里查看。新建房间时或在设置里可以关闭。
- **回复不完整提示**：模型的回复因为达到输出上限、被内容审核截断，或者连接提前断开而不完整时，消息旁边会标注「回复不完整」，可以点「重新生成」。
- **卡住了怎么办**：
  - 模型超过 3 分钟没有任何回应，或者回复到一半超过 90 秒没有新内容，会自动停止并提示，点「重试」即可。
  - 你也可以随时点「停止」。被停止或中断的最后一条 AI 消息下面会出现「重新生成」。
  - 右上角的「继续」按钮可以让守秘人接着说，卡住、被停止或出错之后都可以用。
- **身份边界**：
  - 守秘人负责描写环境、扮演 NPC、裁定结果。
  - 守秘人不替你或 AI 队友说台词、想法或做决定，但可以描写外界对你们的影响，以及你们已经说出的行动带来的结果。
  - 如果模型还是以「【名字】：」的格式替别人说话，这一段会被自动去掉，生成过程中也不会显示出来。消息旁边会标注「已去掉替别人说的话」，鼠标悬停可以看到被去掉的内容。
  - 多人对话里的 AI 也有同样的保护。
- **新手教学模式**：规则第一次出现时，守秘人会附上「规则小贴士」。
- **自动替我掷骰**：在设置里可以打开。

> 规则引擎实现的是 COC 7 的核心机制（d100 检定、成功等级、奖励 / 惩罚骰、孤注一掷、理智检定、车卡公式），职业和技能列表是为新手简化过的版本，不包含任何规则书原文。

## 导出与分享

房间右上角的分享按钮会打开导出窗口，左边选项，右边实时预览：

- **范围**：全部、最近 N 条，或者自定义第几条到第几条。
- **内容开关**：模型和思考强度、时间、思考过程、场景 / 剧本简介、骰子记录。
- **格式**：
  - 长图：下载 PNG，或直接复制到剪贴板，粘贴到聊天软件里。
  - 网页文件：单个 HTML 文件，别人用浏览器就能打开。
  - Markdown
  - 复制文字
  - JSON 备份：包含整个房间，可以在左侧栏的「导入」按钮恢复，也可以发给别人导入。
- 图片和网页都有浅色、深色两种主题。

## 上下文长度

- **默认完整发送**：每次请求都会发送完整的对话记录。推理模型的思考过程不会发回给模型，不占上下文。
- **超出时自动裁剪**：
  - 对话太长、快超过模型的上下文窗口时，会从最早的消息开始省略，并告诉模型前面有内容被省略了。
  - 上下文窗口的大小来自 Magpie 模型列表里的 `context_window`；查不到时按 128k 计算。
  - 估算时给回复（包括思考过程）预留 20% 的空间。
  - 第一次裁剪时会弹出提示，被裁剪过的消息旁边会标注「省略了 N 条早期消息」。
- **跑团里不会忘的东西**：守秘人的系统提示（剧本、规则）、调查员数值、守秘人笔记和秘密备忘每轮都会完整发送，不受裁剪影响。
- **提示缓存**：
  - 每个房间里的每个 AI 都有一个固定的会话 id（`X-Magpie-Session`）。Magpie 靠它把同一段对话留在同一个账号上，服务商那边缓存的提示词才能被复用；在 Magpie 的路由页里也能按会话看到每个 AI 的请求。
  - 流式请求会带上 `stream_options.include_usage`，请服务商报告用量和缓存命中；不认这个参数的服务会自动去掉重发。
  - 用量和缓存命中请在 Magpie 的用量 / 路由页查看。
  - 「设置 → 缓存诊断」会用同一个会话连续发两次相同的提示，看第二次有没有命中缓存，用来区分是服务商 / 渠道的问题还是对话本身的问题。
    - 提示长度有「标准」（约 3k token）和「长」（约 9k token）两档。Gemini 这类服务要求提示足够长才会自动缓存，可以用「长」档测试。
    - 结果可以一键复制。
  - 已知情况：通过 Antigravity 订阅使用 Gemini 时，请求走的是 Google Code Assist 而不是普通的 Gemini API，可能不支持或不报告缓存。
- **方便提示缓存**：会变的内容（调查员数值、物品、笔记、备忘）放在最后一条消息的末尾，不放在系统提示里。这样系统提示和之前的对话在每一轮都保持不变，模型服务的提示缓存可以命中，更快也更省钱。

## 关于 Magpie

Magpie 在本机 `127.0.0.1:3425` 提供 OpenAI 兼容的 `/v1/chat/completions` 和 `/v1/models` 接口，本应用的后端直接调用它：

- 模型列表从 Magpie 动态读取。你在 Magpie 里新接的模型（开源模型、GPT、Gemini、Grok……）会直接出现在模型下拉框里，不用改代码。
- 本机调用不需要真实的 key。默认发送 `magpie-ai-chat`，这样 Magpie 的用量统计里会把这些调用单独记为 ai-chat。
- 调用发生在后端而不是浏览器里，因为 Magpie 会拒绝来自网页的直接请求。所以本应用需要和 Magpie 运行在同一台电脑上。
- 推理模型的思考过程（`reasoning_content` 字段，或正文里的 `<think>` 标签）会单独折叠显示，不计入对话内容。

也可以不用 Magpie，在「设置」里填任何 OpenAI 兼容地址和 key，例如各家官方 API，或 Ollama 的 `http://127.0.0.1:11434/v1`。

## 配置

网页里的「设置」保存在 `data/settings.json`，优先级最高。也可以用环境变量提供默认值（见 `.env.example`）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_BASE_URL` | `http://127.0.0.1:3425/v1` | 模型服务地址，填 `mock` 使用模拟回复 |
| `LLM_API_KEY` | `magpie-ai-chat` | API Key |
| `LLM_DEFAULT_MODEL` | 空 | 新角色的默认模型 |
| `PORT` | `8787` | 后端端口 |
| `DATA_DIR` | `./data` | 数据目录（房间、模板、设置都是 JSON 文件） |

界面支持浅色 / 深色 / 跟随系统，在左下角切换。

```
shared/
  types.ts             前后端共用的数据类型
  text.ts              文本处理（去掉 AI 替别人写的发言）
  coc.ts               COC 7 规则引擎：骰子、检定、成功等级、车卡、角色卡（前后端共用）
server/
  index.ts             Express 接口 + SSE 实时推送 + 托管前端
  runner.ts            对话调度：选下一位发言者、流式生成、插话 / 暂停 / 打断、跑团流程
  prompt.ts            多人对话和拟人模式的提示词
  trpg.ts              守秘人 / AI 队友 / 规则助手的提示词，守秘人指令（骰子、数值、笔记）的解析和结算
  context.ts           上下文长度：估算 token，按模型窗口裁剪早期对话
  scenarios.ts         跑团剧本（原创新手短篇、AI 即兴、自定义）
  scripts.ts           导入剧本：读取 txt / doc / docx，让 AI 分出玩家可见和守秘人专用的内容
  llm.ts               OpenAI 兼容接口的流式调用（含思考强度和模拟模式）
  store.ts             JSON 文件存储（自动迁移旧版本数据）
  presets.ts           内置角色模板和房间预设
web/src/               React 前端
```

几个关键设计：

- **每个 AI 的视角**：调用模型时，这个 AI 自己说过的话作为 `assistant` 消息，其他人（包括你）的话以「【名字】：内容」的形式作为 `user` 消息，同一方连续的消息会合并。
- **对话循环在后端跑**：关掉网页对话也不会乱掉，重新打开就能看到最新状态。前端通过 SSE 实时接收逐字输出。
- **跑团的信息隔离**：
  - 守秘人能看到剧本秘密和所有调查员的数值。
  - AI 队友看不到剧本、骰子指令和你的场外发言。
  - 规则助手看不到剧本秘密。
